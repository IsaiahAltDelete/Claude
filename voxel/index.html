Voxel Maker

A model here is a recipe — a function that fills an empty grid with boxes, spheres and mirrored halves. Nothing was placed by hand, nothing is stored as a blob, and the whole catalogue is about a hundred kilobytes of readable JavaScript. Drag any model to turn it; open one to read the code that built it, edit that code, and watch it rebuild.

Using these in a game

The library is plain scripts with no dependencies, so a page on GitHub Pages can drop in the bundle and build models at load time — a model costs a few milliseconds and a few kilobytes of source, rather than a mesh file per asset. 

<script src="voxel/dist/voxel.js"></script>
<script>
  const knight = VOX.build('knight');       // any name in the catalogue
  VOX.Viewer.attach(canvas, knight);        // drag to turn, wheel to zoom

  const mesh = VOX.mesh(knight);            // greedy-meshed triangles for your own renderer
  VOX.Export.toVOX(knight);                 // MagicaVoxel bytes
  VOX.Export.toOBJ(knight);                 // { obj, mtl }

  VOX.define({                              // or write your own
    name: 'watchdog', category: 'animals',
    build(m, kit) {
      kit.quadruped(m, { coat: kit.P.iron, legTop: 4, bodyTop: 9 });
      m.mirrorX();
    },
  });
</script>

The same code runs in Node with no browser at all, which is how the two reference images below are baked: node tools/voxel-render.mjs rasterises every model on the CPU and writes them out as PNGs, and node tools/voxel-check.mjs asserts that every recipe still builds, still lands on the floor, and still renders to something visible.
